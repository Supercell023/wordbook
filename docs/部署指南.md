# 部署指南

一台 1 核 2G 的云服务器（阿里云/腾讯云/华为云均可，Ubuntu 22.04 / Debian 12）足够一个老师带几十个学生。

## 一、准备

- 服务器有公网 IP，安全组放行 **22、80、443**（或只放行 8787）
- 一个域名（可选，但配 HTTPS 后学生用起来最稳，iOS 的 PWA 也要求 https）
- 把域名 A 记录指向服务器 IP

## 二、上传代码

```bash
# 在本地
scp -r wordbook root@服务器IP:/root/

# 或在服务器上
git clone https://github.com/<你的账号>/wordbook.git && cd wordbook
```

## 三、一键部署

```bash
cd wordbook/server
sudo bash deploy.sh --domain wb.example.com --password '换成你自己的密码'
```

脚本会：

1. 安装 Node.js 22（官方二进制，自动识别 x64/arm64）
2. 把服务端拷到 `/opt/wordbook`
3. 生成 `/etc/wordbook.env`（端口、老师账号密码、数据目录、大模型配置）
4. 注册 systemd 服务 `wordbook.service` 并开机自启
5. 如果给了 `--domain`，安装 Caddy 并自动签 HTTPS 证书，反代到 8787
6. 用 ufw 放行端口

常用参数：

```bash
bash deploy.sh                          # 默认 8787 端口，HTTP
bash deploy.sh --port 8080              # 换端口
bash deploy.sh --domain wb.example.com  # 自动 HTTPS
bash deploy.sh --password 'xxxx'        # 指定老师密码
```

重复执行是安全的：会保留 `data/`，只更新代码和服务配置。

## 四、验证

```bash
systemctl status wordbook
curl -s localhost:8787/api/health   # 应返回 {"ok":true}
journalctl -u wordbook -n 50        # 出问题看这里
```

浏览器打开：

- 学生端 `http://服务器IP:8787/`（或 https 域名）
- 老师端 `http://服务器IP:8787/admin`

老师账号默认 `teacher`，密码是部署时设置的那个；首次登录后在「激活码」里生成一批码发给学生。

## 五、接大模型（可选）

编辑 `/etc/wordbook.env`：

```ini
LLM_URL=https://api.deepseek.com/v1/chat/completions
LLM_KEY=sk-xxxx
LLM_MODEL=deepseek-chat
```

然后 `systemctl restart wordbook`。老师端点「AI 点评」时走大模型；没配或调用失败会自动退回本地规则分析，功能不受影响。

也可以换成任何 OpenAI 兼容接口（MIMO、通义、智谱等），只改 `LLM_URL` / `LLM_MODEL` 即可。

## 六、备份与迁移

所有数据都在一个文件里：

```bash
/opt/wordbook/data/db.json     # 学生、激活码、上传记录、任务、日志
/opt/wordbook/data/secret      # 令牌签名密钥（丢了所有人要重新登录/绑定）
```

定期备份这两个文件即可。换服务器时把 `data/` 整个拷过去，学生不用重新绑定。

## 七、常见问题

**学生打不开页面**
- 检查安全组/防火墙端口
- 用 `curl -I http://服务器IP:8787/` 确认服务在跑
- 学校网络可能屏蔽非标准端口，换 80/443 或配域名 https

**手机上提示「不安全」**
- 配了域名就用了 Caddy 的自动 HTTPS；没有域名就只能是 http，微信内打开可能提示风险，用「在浏览器打开」

**iOS 学生怎么装**
- 不能装 APK；Safari 打开 https 地址 → 分享 → 添加到主屏幕，即得到全屏 PWA
- 也可以给他们 Xcode 工程自行签名（需要 Mac），见 `ios/README.md`

**老师密码忘了**

```bash
sudo -i
cd /opt/wordbook
ADMIN_PASS='新密码' node server.js   # 启动一次会重置
# 或者改 /etc/wordbook.env 后 systemctl restart wordbook
```

**数据重置**

```bash
systemctl stop wordbook
rm -f /opt/wordbook/data/db.json
systemctl start wordbook   # 重新生成，老师密码回到初始值
```

# 八、安装为 PWA（添加到主屏幕）

## 8.1 为什么之前装不上

| # | 根因 | 现象 |
|---|------|------|
| 1 | `tools/build.py` 只产出 `dist/vocab.html`，`build.sh` 以前**没把 manifest / sw.js / icons 同步进 `dist/`** | 拿 `dist/` 当站点根托管时 `manifest.json`、`sw.js`、`icons/*` 全 404 → Chrome 报 “Manifest is not detected” / 无 Service Worker → 永远没有安装入口 |
| 2 | manifest 的 `start_url` 是 `./`，服务端 `/` 会 302 跳到别处 | 安装校验里 start_url 落在重定向，部分版本直接不给安装入口 |
| 3 | 手机用 `http://<局域网IP>:8787` 打开属**非安全上下文** | `navigator.serviceWorker` 不可用；页面里的注册代码把错误静默吞掉，看起来正常但永远装不上 |
| 4 | 图标不全（缺 favicon-32、iOS/Android 资源目录里没同步 icons、历史 PNG 尺寸未校验） | iOS 桌面图标空白；Chrome 提示 icon size mismatch |
| 5 | `theme_color`/`background_color` 是 `#eef1f6`，与页面米色纸感 `#f4efe4` 不符 | 启动闪屏颜色突兀（不影响可安装性） |

**可安装的四个硬条件**：HTTPS（或 localhost）+ 可访问的 manifest（含 192 与 512 图标）+ 成功注册的 Service Worker + `start_url` 在 `scope` 内。

## 8.2 资源拓扑与四个同步目标

真源在 `web/`，同步后下面 4 个目录**各自都要是一份完整站点**（`vocab.html` + `manifest.json` + `sw.js` + `icons/`）：

1. `dist/` —— 交付/静态托管用（**之前缺的就是这一环**）
2. `server/public/` —— 本地 HTTP 服务根
3. `android/assets/` —— Android 壳内置资源
4. `ios/Resources/www/` —— iOS 壳内置资源

```bash
cd /root/workspace/wordbook
./build.sh all      # build → icons → sync → verify（无 ecdict.csv 时跳过 build）
./build.sh sync     # 只同步；dist/vocab.html 缺失会从其它三个目录反补
./build.sh icons    # 只重新生成 PNG 图标
./build.sh verify   # 一致性校验，失败返回非零
```

`sync` 会先用 `python3 web/icons/make_icons.py --check` 校验 PNG 真实尺寸，不符或缺失就自动重生成，然后复制到 4 个目录。
`verify` 校验：manifest JSON 可解析、必备字段齐全、`display` 合法、存在 `maskable` 的 512 图标、4 个目录文件齐全、**manifest 声明的 PNG 实际尺寸与声明一致**、`vocab.html` 含 `rel="manifest"` / `serviceWorker` / `apple-touch-icon`。

## 8.3 图标规范

| 文件 | 尺寸 | 用途 |
|------|------|------|
| `icon-192.png` | 192×192 | Android 主屏（必需） |
| `icon-512.png` | 512×512 | 启动闪屏 / 安装对话框（必需） |
| `maskable-512.png` | 512×512 | Android 自适应图标（`purpose:"maskable"`） |
| `apple-touch-icon.png` | 180×180 | iOS 主屏，**不要透明底**（透明会变黑） |
| `favicon-32.png` | 32×32 | 浏览器标签页 |
| `icon.svg` / `maskable.svg` | 矢量 | 高分屏兜底 |

风格：米色纸感 `#f4efe4` 底、墨蓝书封 `#2d4a74`、书脊 `#24405f`、书签金 `#c08a2e`。
重画只改 `web/icons/make_icons.py` 顶部颜色常量，然后 `./build.sh icons sync`。该脚本纯标准库（zlib+struct），不依赖 Pillow。

## 8.4 HTTPS 是硬门槛

Service Worker 只在安全上下文可用：`https://…` 或 `http://localhost` / `http://127.0.0.1`。

- 手机直接开 `http://服务器IP:8787` **一定装不上**，这是浏览器规定，不是代码 bug；
- 正确做法：`bash deploy.sh --domain wb.example.com`（Caddy 自动证书，反代 8787）；
- 内网临时验证：`adb reverse tcp:8787 tcp:8787` 后用 `http://localhost:8787`；
- 自签证书：`TLS_KEY=… TLS_CERT=… node server/server.js`，手机需手动信任证书才算安全上下文。

`server/server.js` 支持可选 HTTPS；未配 TLS 时启动日志会打印「当前为 http，仅 localhost 可安装 PWA」。

## 8.5 安装步骤

- **Android（Chrome / Edge）**：打开 `https://<域名>/vocab.html` → 菜单出现「安装应用 / 添加到主屏幕」，或地址栏右侧安装图标 → 安装后从桌面启动应为独立窗口（无地址栏），闪屏米色。
- **iOS（必须 Safari）**：打开同一 URL → 分享 → **添加到主屏幕**，图标取 `<link rel="apple-touch-icon">`（180×180）。
- **桌面 Chrome**：地址栏安装图标，或菜单 →「安装 词书背单词…」。
- **国内手机浏览器**：QQ/UC/百度等不一定支持 PWA，引导用 Chrome 或 Safari。

## 8.6 验证清单

```bash
BASE=https://wb.example.com        # 或 http://127.0.0.1:8787
curl -sI $BASE/manifest.json       # 200 + application/manifest+json
curl -s  $BASE/manifest.json | python3 -m json.tool >/dev/null && echo "manifest JSON OK"
for f in icon-192.png icon-512.png maskable-512.png apple-touch-icon.png favicon-32.png; do
  printf '%s -> ' "$f"; curl -s -o /dev/null -w '%{http_code} %{content_type}\n' "$BASE/icons/$f"
done
curl -sI $BASE/sw.js               # 200 + Service-Worker-Allowed: /
```

Chromium 安装性（最权威），用本机 Playwright 自带浏览器：

```js
// 存为 /tmp/check-installable.mjs，执行：node /tmp/check-installable.mjs http://127.0.0.1:8787/vocab.html
import { chromium } from '/root/workspace/wordbook/tests/node_modules/playwright-core/index.mjs';
const url = process.argv[2];
const b = await chromium.launch({
  executablePath: '/root/.cache/ms-playwright/chromium-1248/chrome-linux-arm64/chrome',
  args: ['--no-sandbox', '--disable-dev-shm-usage'],
});
const p = await b.newPage();
const cdp = await p.context().newCDPSession(p);
await cdp.send('Page.enable');
await p.goto(url, { waitUntil: 'networkidle' });
await new Promise(r => setTimeout(r, 1500));
console.log('installabilityErrors =', JSON.stringify(await cdp.send('Page.getInstallabilityErrors'), null, 2));
console.log('manifest errors =', JSON.stringify((await cdp.send('Page.getAppManifest')).errors, null, 2));
console.log('sw registrations =', await p.evaluate(() => navigator.serviceWorker.getRegistrations().then(r => r.length)));
await b.close();
```

通过标准：`installabilityErrors.errors` 为空、manifest 无 error、SW 注册数 ≥ 1。
用 `http://127.0.0.1` 测才享受安全上下文豁免；换成局域网 IP 必然失败。
DevTools → Application 也能看：Manifest 无红字、Service Workers 为 `activated and is running`、右上角 Installability 显示可安装。

## 8.7 故障对照表

| 现象 | 大概率原因 | 处理 |
|------|-----------|------|
| 没有安装按钮，Application 里 Manifest 空白 | manifest 404 / JSON 语法错 / MIME 不对 | `curl -sI /manifest.json`；`./build.sh verify` |
| “No matching service worker detected” | sw.js 404、注册路径错、或非安全上下文 | 看 Console 的 ServiceWorker 报错；换 https 或 localhost |
| 有 Manifest 有 SW 仍不给装 | 图标不足 192/512、start_url 跳转、display 非法 | 跑 8.6 的脚本看 `installabilityErrors` |
| 桌面图标模糊/空白 | 缺 512，或 apple-touch-icon 没同步 | `./build.sh icons sync` 后卸载重装 |
| 装完点开白屏 | `start_url` 指向不存在文件 | 确认 `start_url` 为 `./vocab.html` 且文件在同步目录里 |
| 改了页面重装还是旧内容 | SW 命中旧缓存 | 已做网络优先 + 版本清理；仍顽固则在 DevTools → Application → Storage → Clear site data |
| iOS 状态栏/标题不对 | 缺 apple-mobile-web-app-* | 见 8.8 |

## 8.8 页面 `<head>` 需要的标签

现有模板已含 manifest、`theme-color`、`apple-mobile-web-app-*`、`apple-touch-icon`。**建议补**这 4 行（放在已有 `<link rel="manifest">` 附近）：

```html
<link rel="icon" href="icons/favicon-32.png" sizes="32x32" type="image/png">
<link rel="icon" href="icons/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" sizes="180x180" href="icons/apple-touch-icon.png">
<meta name="theme-color" media="(prefers-color-scheme: dark)" content="#0e1117">
```

- 前两行给标签页 favicon（SVG 优先、PNG 兜底）；
- 第三行给 `sizes` 提示，iOS 会挑这张；
- 第四行让暗色模式状态栏跟随页面暗色背景 `#0e1117`（亮色已有 `#f4efe4`）。

## 8.9 回滚

`dist/`、`server/public/`、`android/assets/`、`ios/Resources/www/` 都是生成物，可随时从 `web/` 重建：

```bash
git checkout -- web/manifest.json web/sw.js build.sh server/server.js
git clean -fd dist server/public/icons android/assets/icons ios/Resources/www/icons
./build.sh all
```
